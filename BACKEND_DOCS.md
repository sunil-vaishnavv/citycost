# CityCost Backend Documentation
## Overview
This document describes the new backend architecture using MySQL + Groq, replacing the original demo/hardcoded data system, while maintaining complete backward compatibility.

## API Flow
### GET /api/cities
1. Try Numbeo API (if configured, for backward compatibility)
2. Else, try MySQL database for all cities
3. Else, fall back to original DEMO_CITIES array

### GET /api/city_prices?query=...
1. Try Numbeo API (if configured)
2. Else, try MySQL:
   a. Check if city exists (cache hit)
   b. If yes: return data from MySQL
   c. If no: generate via Groq, save to MySQL, then return
3. Else, fall back to original demo/procedural generation

### POST /api/ai_summary
1. Try Groq API for summary
2. Else, fall back to original procedural summary

---
## Cache Strategy
- **Cache Hit**: When city data exists in MySQL
- **Cache Miss**: When city data is not in MySQL; generate via Groq and save for next time
- **Log Every Request**: Every API call is logged to `logs` table with timing, cache status, errors

## Database Setup
1. Create a MySQL database named `citycost_global`
2. Apply schema: `mysql -u root -p citycost_global < db/schema.sql`

---
## Backward Compatibility
- All original APIs work exactly as before
- Original DEMO_CITIES array remains as final fallback
- Numbeo API still supported if configured
- All frontend code unchanged
- All SEO/robots/sitemap routes unchanged

---
## Installation Steps
1. `npm install`
2. Copy `.env.example` → `.env` and fill in secrets
3. Create MySQL database
4. Apply `db/schema.sql` to database
5. Run: `npm run dev` (or `npm run start` for production)
